# 이직 준비 채용 공고 알림 시스템 정리

작성일: 2026-09-13 (이경은님)

## 1. 전체 구조

이직 준비를 위해 채용 공고를 자동으로 감지하고 알려주는 시스템을 3개 채널로 구축했습니다.

| 채널 | 방식 | 주기 | 알림 수단 | 상태 |
|---|---|---|---|---|
| ① Claude 자동 알림 | Claude의 WebSearch로 직접 검색 (API/키 불필요) | 3시간마다 | 푸시(폰 알림) | ✅ 정상 작동 확인됨 |
| ② GitHub Actions 봇 | Python 스크립트, 사람인 공식 API 등 사용 | 3시간마다 | 텔레그램 + 슬랙 | ⚠️ 사람인 API 승인 대기 중이라 사실상 0건 |
| ③ 네이버메일 포워딩 | 사람인이 보내주는 채용 알림 메일을 IMAP으로 읽어 전달 | ②와 같은 워크플로 안에서 실행 | 텔레그램 + 슬랙 | ✅ 코드상 정상 (실제 메일 수신 여부는 별도 확인 필요) |

세 채널 모두 공통 원칙: **새로운 공고가 없으면 알림을 보내지 않음** (조용히 넘어감).

## 2. 채널별 상세

### ① Claude 3시간 자동 알림 (스케줄 작업)
- 이름: "이직 준비 - 채용 공고 자동 알림 (이경은)"
- 검색 대상: 사람인, 원티드, 잡코리아, 인크루트 (WebSearch로 `site:도메인 키워드 채용` 형태 검색)
- 관심 직무: 행사/이벤트 기획·운영, 콘텐츠 기획/PD, 경영지원/매니저
- 새 공고 발견 시: 프로젝트 "개인"의 `claude/맞춤 지원서 초안 모음.md`에 회사별 자기소개서 초안 + 이력서 강조 포인트를 자동 작성해 누적 저장
- 알림 채널: 푸시만 (이메일은 꺼둠 — 매번 결과와 상관없이 이메일이 와서 번거로웠음)
- 상태 저장 위치: 프로젝트 문서 `claude/job-alert-seen.json` (+ 로컬 백업)
- **[대화 중 미확정]** 사용자가 "자동 알림 전부 중단"을 요청했으나, 실제 비활성화 승인 단계에서 거절되어 **아직 켜져 있는 상태**. 계속 끌지 여부 확인 필요.

### ② GitHub Actions 봇 (텔레그램/슬랙)
- 저장소: `gnuykel2066-cyber/hiring` (Private)
- 파일: `job_alert.py`, `requirements.txt`, `seen_jobs.json`, `.github/workflows/job-alert.yml`
- 사용 소스:
  - 사람인 공식 Open API — **승인 대기 중** (승인 전엔 빈 결과, access-key 없으면 자동으로 건너뜀)
  - **사람인 검색결과 페이지 직접 조회 (신규, 2026-09-14 추가)** — 공식 API 승인 전까지 임시 대체 수단. 오픈소스 참고([`yujeong0411/recruit_crawler`](https://github.com/yujeong0411/recruit_crawler))를 바탕으로, 사람인 검색 페이지가 내부적으로 호출하는 비공개 엔드포인트(`zf_user/search/get-recruit-list`)를 그대로 조회해서 키워드별 공고를 가져옴. 사람인 robots.txt상 이 검색 경로는 크롤링 금지 대상이 아님(금지 대상은 상세페이지 `zf_user/recruit/view/`). `ENABLE_SARAMIN_SCRAPE = True`로 켜져 있음. **⚠️ 이 샌드박스 환경 자체의 네트워크 정책이 saramin.co.kr을 막고 있어서 여기서는 직접 실행 테스트를 못 했음 — GitHub Actions에서 실제로 공고가 잡히는지 다음 실행 로그로 꼭 확인 필요**
  - 원티드 비공식 API — GitHub Actions에서 403으로 완전히 막혀서 **꺼둠** (`ENABLE_WANTED_SUPPLEMENT = False`)
  - 구글 Custom Search API(CSE) — 신규 프로젝트에 "This project does not have the access to Custom Search JSON API" 403 에러로 막혀서 **꺼둠** (`ENABLE_GOOGLE_CSE = False`). 코드는 남겨뒀고, 나중에 구글 정책이 풀리면 다시 켤 수 있음
- 고쳤던 버그: 검색 결과가 계속 0건이면 "첫 실행"으로 영원히 착각해서 "초기 설정 완료" 알림이 3시간마다 반복 발송되던 문제 → `initialized` 플래그를 파일에 별도 기록하도록 수정, 해결됨
- 사람인 검색결과 스크래핑이 정상 작동하면 이 채널도 실제 공고를 찾아 알림을 보내기 시작함 (기존엔 API 승인 전이라 사실상 0건이었음)

## 3. 잡코리아 관련 별도 이슈

- 잡코리아는 robots.txt로 크롤링을 막아놨고 개인용 공식 API도 없어서, 코드(Python)로 "새 잡코리아 공고 자동 발견"은 현재 불가능
- 대신 채널 ①(Claude 자동 알림)이 WebSearch로 잡코리아 개별 공고(`jobkorea.co.kr/Recruit/GI_Read/숫자` 패턴)를 걸러내는 방식으로 이미 커버 중
- 추가로 잡코리아의 "AI 맞춤 추천" 개인화 페이지(`jobkorea.co.kr/User/AI?SourceType=11`)를 활용하고 싶다는 요청이 있었으나:
  - 로그인 세션 기반 개인화 페이지라 자동 스케줄로는 확인 불가 (사용자 컴퓨터가 항상 켜져 있고 Chrome이 로그인돼 있어야 함)
  - **결정: 자동화하지 않고, 필요할 때 사용자가 요청하면 그 순간에 Claude in Chrome(또는 데스크톱 앱 연결)으로 확인하는 방식으로 진행**

## 3-1. 상태 파일 커밋 충돌 재발 (2026-09-22)

- 증상: `변경된 상태 파일 커밋` 단계에서 `error: you need to resolve your current index first` / `seen_jobs.json: needs merge`
- 원인: 이전에 고쳤던 "Re-run(재실행)이 오래된 워크플로 스냅샷을 그대로 쓰는" 문제와 같은 계열. 오래된 실행을 다시 돌리면 그 시점의 커밋을 기준으로 체크아웃하는데, 그 사이 `seen_jobs.json`이 많이 바뀌어 있으면 `git pull --rebase --autostash`가 되돌리는 stash(작업 중이던 변경 내용)를 최신 파일에 다시 얹는 과정에서 충돌이 나고, 그 충돌이 안 풀린 채로 다음 커밋 단계까지 넘어가서 워크플로가 빨간 X로 실패함
- 조치: `.github/workflows/job-alert.yml`의 "원격 변경사항 먼저 반영" 단계를 고쳐서, 충돌이 나면 그 실행에서는 **상태 파일 커밋만 조용히 건너뛰도록** 만듦(`git rebase --abort` → `origin`의 최신 상태로 리셋 → 다음 커밋 단계는 `skip_commit` 플래그로 건너뜀). 이러면 오래된 실행을 재실행해도 워크플로가 빨간 X로 죽지 않고, 그냥 이번 실행만 "새로 감지한 공고를 기록에 안 남기고" 넘어감(다음 정상 실행 때 자동으로 다시 맞춰짐 - 최악의 경우 같은 공고 알림이 한 번 더 갈 수 있는 정도)
- **사용자 행동 요령(중요): Actions 탭에서 예전에 실패했던 회차의 "Re-run jobs" 버튼은 계속 누르지 말 것.** 수동으로 다시 돌리고 싶을 때는 항상 워크플로 개요 페이지의 **"Run workflow"** 버튼을 사용 (최신 main 기준으로 새 실행을 시작함)
- GitHub 저장소의 `.github/workflows/job-alert.yml`을 이 수정본으로 교체 필요 (`gnuykel2066-cyber/hiring`과, 공유용 템플릿 저장소 둘 다 동일하게 반영해둠)

## 3-2. 네이버메일 알림 정리 (2026-09-23)

- 증상: 슬랙에 사람인 "이력서 열람" 알림 메일(추천 공고가 아닌, "OOO님의 이력서를 열람하였습니다" 메일)까지 전달되고, 링크도 추적용 리다이렉트(`mcheck_bridge.php?...&url=...`) 주소가 여러 개 중복으로 길게 붙어서 옴. 오류는 아니고, 발신 주소만으로 필터링하던 원래 설계가 사람인이 보내는 모든 종류의 메일을 다 걸러낸 것.
- 조치 (`naver_mail_alert.py`):
  - `EXCLUDE_SUBJECT_KEYWORDS = ["열람", "조회"]` 추가 — 제목에 이 단어가 있으면 채용 추천이 아니라고 보고 알림 없이 조용히 seen 처리만 함(사용자가 "제목으로 걸러서 추천 메일만 받기"를 선택함)
  - `simplify_link()` 추가 — 사람인의 `mcheck_bridge.php` 리다이렉트 추적 링크를 실제 목적지 링크로 풀고, `utm_*` 추적 파라미터를 제거. 도메인만 남고 경로/쿼리가 없는 링크(헤더 로고 등)는 `is_useful_link()`로 걸러냄. 결과적으로 같은 목적지를 가리키던 중복 링크들이 하나로 합쳐짐
  - `MAX_LINKS_PER_MAIL` 15 → 5로 축소 (링크가 정리된 뒤라 5개면 충분)
  - 공유용 템플릿 저장소(`job-alert-bot-template/naver_mail_alert.py`)에도 동일하게 반영, 개인정보 유출 없는지 재확인 완료
- GitHub 저장소의 `naver_mail_alert.py`를 이 수정본으로 교체 필요
